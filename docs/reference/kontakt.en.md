## Reporting a bug

A report with a diagnostics package can be acted on straight away. A report without one
usually ends in a request for more, so it is worth attaching it from the start.

1. Open **Settings → Diagnostics**.
2. Choose **Export diagnostics ZIP**.
3. Send the file to the address above together with a description.

Give three things in the description:

- **what you were doing** - the specific steps, not "the import does not work";
- **what you expected**;
- **what happened instead** - including the text of the message, if one appeared.

If the application does not start at all, the package cannot be exported from Settings -
use the button on the start screen. This is described in
[Application does not start](../troubleshooting/aplikacja-nie-startuje.md).

## What not to send

!!! warning "The diagnostics package is safe, your own attachments may not be"

    The diagnostics ZIP contains no source scenes, annotations or full geometries - it
    can be sent without concern. Responsibility for additional attachments rests with the
    sender.

Do not attach source scenes, vendor packages or datasets. They are large, and they may be
subject to distribution restrictions. If the bug concerns one particular scene, give its
name and vendor - that is enough to reproduce the problem.

Check screenshots before sending them for paths, project names and coordinates of areas
you would rather not disclose.

## Requests for changes

Describe **the problem you want solved**, not only the solution you have in mind.
Knowing what you are trying to achieve often leads to a simpler answer than the original
idea - sometimes the function already exists under a different name.
